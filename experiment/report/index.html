Executive Summary

EpochLex is an open-source, searchable reference work for terminology of the AI era. The project began on August 28, 2026, as a relatively small dictionary concept and developed into a 365-entry public reference work with structured provenance, dedicated term pages, pronunciation, responsive browsing, related-term discovery, a Progressive Web App, Word of the Day, contributor infrastructure, and a documented editorial and architectural model.

The project also became an experiment in AI-assisted development. ChatGPT was used extensively alongside GitHub and repository-based development during the initial phase, assisting with product exploration, implementation, debugging, documentation, research organization, quality assurance, and editorial support. On September 17, Codex was added to the existing workflow as a more repository-oriented implementation agent. The development process remained human-directed and human-reviewed throughout.

The strongest finding in the current report is that AI materially reduced the distance between product intent and working implementation. That acceleration did not remove the need for planning or engineering discipline. As the project grew, architecture, QA, source control, documentation, validation, editorial standards, and human review became more explicit rather than less important.

The report also treats ambiguity as an experimental variable and distinguishes different classes of failure. It does not interpret repository throughput as a productivity multiplier, labor saving, or proof of superiority over conventional development because no matched control project or reliable historical labor record exists.

The first phase suggests that AI changes the rate at which ideas can be converted into implementation more clearly than it changes the need for judgment.

Working software became part of the thinking process, while the value of that acceleration increasingly depended on the surrounding system’s ability to distinguish useful output from plausible but incomplete output.

The first phase demonstrates AI participation across a broad product-development lifecycle while also documenting consequential human direction. Faster implementation did not remove conventional development practice; as the project grew, architecture, source control, QA, documentation, validation, and human review became more explicit.

Limits carried forward

  • No matched control project.
  • No systematic historical human-labor tracking.
  • Incomplete historical token accounting.
  • Incomplete exact model timeline.
  • Repository and conversation records are substantial but not forensically complete.
  • Results should not automatically be generalized to projects with substantially different risk profiles, architectures, or teams.
