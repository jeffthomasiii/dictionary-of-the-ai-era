# DeepSeek entry research decision

Status: Proposed for review in the DeepSeek named-entity slice.

## Decision

Publish **DeepSeek** as an `organization` entry and **DeepSeek-R1** as a `model-family` entry.

Do not create a second entry titled simply **DeepSeek** for the consumer product. The same name is used for the organization and the web/app brand, so two identically titled records would reduce reader clarity and conflict with the existing backlog guidance.

Do not create separate DeepSeek-V3 or DeepSeek-V4 entries in this slice. Current first-party materials show continuing versioned V-series releases, including V3.x and V4.x. Under EpochLex's version policy, those releases are better represented in DeepSeek history/provenance unless a particular version later demonstrates distinct reader value sufficient for a separate entry.

DeepSeek-R1 is treated differently because first-party materials identify an R1 series and distinguish its reasoning-model lineage from the V-series releases. Its widespread use as a named model line gives it distinct reader value beyond the organization entry.

## Evidence basis

Primary-source research reviewed for this decision includes:

- DeepSeek Transparency Center, which lists major released model lines and release history: https://www.deepseek.com/en/transparency/
- DeepSeek official site, which distinguishes the DeepSeek web/app experience from named models and the API platform: https://www.deepseek.com/en/
- DeepSeek model-mechanism disclosure, which identifies Hangzhou DeepSeek Artificial Intelligence Co., Ltd. and describes DeepSeek as a research team focused on foundational model technology: https://cdn.deepseek.com/policies/en-US/model-algorithm-disclosure.html
- DeepSeek-R1 official repository, which describes DeepSeek-R1 and DeepSeek-R1-Zero as R1 models and documents the R1 distillation family: https://github.com/deepseek-ai/DeepSeek-R1
- DeepSeek API documentation, which currently exposes specific V4 model identifiers rather than a generic model simply named DeepSeek: https://api-docs.deepseek.com/quick_start/pricing/

This planning note is not itself evidence for dictionary claims. Published records must carry claim-specific provenance under the normal EpochLex editorial process.
